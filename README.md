# Banana_Dock · 车机悬浮 Dock

跑在安卓 9（API 28）车机上的悬浮 Dock。当前版本 **4.0**（versionCode 434）。

- 包名：`com.car.dockbar`
- 应用名：`Banana_Dock`
- 屏幕按 **1920 × 1080、DPI 160**（1dp = 1px）写死，不读系统显示参数
- 窗口默认 **1920 × 128 px**，贴底。y = 1080 − 128 − 距边 0 = **952**
- 车控走反射，编译期不依赖厂商 jar
- 歌曲走通知使用权里的 **MediaSession**。`com.flyme.auto.music` 没有会话时再读它的通知

---

## 一、默认布局

默认布局为 10 个条目；宽度不再按等宽槽切。固定项的标称宽度锁死，只剩音乐卡弹性伸缩（295～500px）。

| 顺序 | 控件 | 标称宽 px |
| --- | --- | --- |
| D01 | 返回桌面 | 98 |
| D02 | 音乐信息 | 295～500 |
| D04 | 车机设置 | 98 |
| D05 | 快捷应用 | 98 |
| D06 | 主驾温度 − 值 + | 290 |
| D12 | 空调风向 | 98 |
| D08 | 风速 − 值 + | 220 |
| D18 | 内外循环 | 98 |
| D19 | 座椅 | 98 |
| D07 | 副驾温度 − 值 + | 290 |

默认 10 项的固定项标称宽度合计 **1388px**。在 1920px 屏幕上，音乐卡达到上限 **500px**，其余条目按比例分摊剩下的 1420px。删除条目后也会重新分配占位；没有音乐卡时，剩余按钮仍铺满整栏。图标和文字大小不随条目数量自动放大；仅剩音乐卡时居中显示。

图标默认 **65px**（返回桌面圆环、音量喇叭都是 0.8 倍）。风速组合里的 ± 箭头是 **40px**。1 槽项标称 98px，温度组合 290px，风速组合 220px。圆角默认 **14px**。

歌词、音量、座椅通风、前挡加热、后挡除霜、方向盘加热和座椅加热默认不在栏上，要在「Dock 图标管理」中手动添加。

## 二、控件行为

| 控件 | 单击 | 长按 |
| --- | --- | --- |
| 返回桌面 | 回桌面 | 打开最近任务 |
| 音乐卡 | 打开当前播放器 | — |
| 音乐卡播放键 | 播放 / 暂停 | 下一曲 |
| 歌词 | 开 / 关歌词悬浮窗 | 打开本应用 |
| 音量 | 音量弹窗（媒体、导航） | — |
| 车机设置 | 打开车机设置 | 打开 Dock 设置页 |
| 快捷应用 | 打开 2×3 面板 | 去设置里选这 6 个应用 |
| 主驾温度 ± | 温度 ±1℃ | — |
| 主驾温度数字 | 温度弹窗 | 切换 AC |
| 副驾温度 ± | 温度 ±1℃ | — |
| 副驾温度数字 | 温度弹窗 | 切换双温同步 |
| 风向 | 风向弹窗 | 打开空调 |
| 座椅通风 | 降档（关时跳到 3） | 升档（3 档再按关） |
| 风速 ± | 手动 0～9；AUTO 开着时改 AUTO 1～5 | — |
| 风速数字 | 开 / 关 AUTO | 关风速 |
| 内外循环 | 内 / 外切换 | — |
| 座椅 | 座椅弹窗 | — |

按下是整颗按钮的水波纹（`bg_item_press`）。

音量按钮上的喇叭是图标尺寸的 0.8 倍。右下角用前景色写媒体当前档位，字号是图标尺寸的 0.4 倍（65px 图标时约 26px）。数字贴着按钮右下角，再上移 25px、左移 3px。深色界面白字，浅色界面黑字，跟喇叭图标同一套换色。

音量弹窗按 1.8 倍画，样式和空调弹窗一样：贴着这个按钮、点外面关闭、6 秒收起。里面两列，上加、中条、下减，条上的数字就是系统流索引，也可以按住滑动。

| 列 | 系统流 | 这台车日志里的上限 |
| --- | --- | --- |
| 媒体 | `STREAM_MUSIC` = 3 | 39 |
| 导航 | `STREAM_NAVI_TTS` = 15 | 39 |

界面是几，`AudioManager.setStreamVolume` 就写几。不再加减 5。`CarAudioManager.setGroupVolume` 在普通应用上会抛异常，所以不用它。

Dock 被应用名单藏起来之后，底部小横条上滑临时唤出。倒计时从松手、弹窗关掉之后才开始，默认 5 秒。

Dock 图标管理使用实际 Dock 控件预览：上方显示尚未添加的内置控件，长按固定 **300ms** 拖入预览；预览内长按拖动做插入排序；拖出预览并松手移除，内置控件回到候选区。第三方应用通过独立入口选择，区分系统应用和个人应用，并支持名称/包名搜索。预览不会执行车控或打开应用；固定 300ms 只作用于编辑器，不改变实际 Dock 的长按行为。

快捷应用是独立的 **2×3 固定槽位面板**。设置页可点击空位批量管理、点击已填格替换、点击红圆白色 × 清除、长按拖动交换两个位置；删除后保留空位，不让其它应用顺位。Dock 弹窗使用同一份固定槽位数据，保持原有打开应用与拖动交互。

## 三、外观

四选一：纯色、透明、渐变、模糊（测试中）。

“透明”使用 `TYPE_APPLICATION_OVERLAY` + `PixelFormat.TRANSLUCENT`，不绘制背景色、渐变或模糊底图，图标和文字正常绘制。视觉透明不代表触摸自动穿透。

目前“模糊”入口是**透明灰色蒙层试验，并非真实背景模糊**：纯透明底层上绘制灰色，通过两个滑杆分别控制灰色深浅与合成透明度；不录屏、不采样屏幕、不使用壁纸替代后方画面。透明度 100% 时完全透出背景，0% 时灰色层不透明。Android 9 没有普通应用通用的跨窗口高斯模糊 API，不能把该试验效果描述成真实毛玻璃。

纯色模式下，只有系统桌面（`com.android.launcher3` 或当前默认 HOME）在前台时，底色自动改成透明。其它应用在前台仍是纯色。

## 四、车控通道

Dock 上的 ± 每次 **1℃**。温度弹窗列表仍是 15.5～28.5℃，相邻一档相差 0.5℃。写给车机的编码是 `round(℃ / 0.2)`。zone 用座椅位：主驾 **1**，副驾 **4**。

| 功能 | functionId | zone | 取值 |
| --- | --- | --- | --- |
| 手动风量 | `0x10020100` | `0x8` | 复合编码 0～9 档 |
| AUTO 风量 | `0x10020200` | `0x8` | 1～5 档，低字节乱序：1→`0x04`，2→`0x01`，3→`0x02`，4→`0x03`，5→`0x05` |
| AUTO 总开关 | `0x10010200` | `0x80000000` | 裸值 0 / 1 |
| 主驾温度 | `0x10060100` | `1` | `round(℃ / 0.2)` |
| 副驾温度 | `0x10060100` | `4` | 同上 |
| 双温同步 | `0x10060500` | `0x80000000` | 0 / 1 |
| AC | `0x10010300` | `0x80000000` | 0 / 1 |
| 风向 | `0x10070100` | `0x8` | 复合编码 1～7 |
| 内外循环 | `0x10030100` | `0x80000000` | 外循环裸值 0，内循环 `0x10030101` |
| 主驾座椅通风 | `0x10050100` | `1` | 0～3 |
| 主驾座椅加热 | `0x10050200` | `1` | 0～3 |
| 副驾座椅通风 | `0x10050100` | `4` | 0～3 |
| 副驾座椅加热 | `0x10050200` | `4` | 0～3 |
| 方向盘加热 | `0x10090100` | `1` | 0～3 |
| 前挡加热 | `0x10040100` | 全局 | 开关 |
| 后挡除霜 | `0x10040300` | 全局 | 开关 |

座椅通风不是 `0x10050000`，座椅加热不是 `0x10050100`。循环和 AUTO、AC、双温同步的 zone 是整车 `0x80000000`，不是 `0x8`。

AUTO 打开时，风速 ± 写 `0x10020200`，不写手动风量。

## 五、音乐

先绑活跃 MediaSession。歌名、歌手、播放状态从会话读。

封面按这个顺序取：会话里的位图、`ALBUM_ART_URI` 一类本地路径或 `content://`、播放器通知上的大图。酷狗车机版（`com.kugou.android.auto`）经常只有歌名没有位图，封面在它自己的通知大图里。

`com.flyme.auto.music` 不进活跃会话。系统那条「QQ音乐正在运行」不当成歌曲。有真实歌名的通知才用。

## 六、设置页

左侧：悬浮 Dock 栏、外观与风格、Dock 图标管理、歌词悬浮窗、常驻应用设置、诊断与日志。

悬浮 Dock 栏右侧有宽、高、距边。高的默认值是 **128**。原来存成 120 的会在第一次读取时改成 128。

设置页整体为深灰＋蓝色主题，内容区域底部固定让出 **128 物理像素**给实际 Dock，左右背景和分割线延伸到底。各设置 Activity 相对原尺寸缩为 0.9 倍；主设置 Activity 的最终密度系数为 `1.2×0.9=1.08`，图标管理子页为 `1.0×0.9=0.9`，不是修改系统 DPI 或实际 Dock 大小。

“外观与风格”包含背景形态可视化选择、尺寸与比例、日夜透明度和分隔线开关。应用外观在“显示分隔线”开关切换时自动保存并应用。

“常驻应用设置”显示实际已安装应用，分为系统应用和个人应用两栏，每栏 5 列、默认 4 行；图标 45×45dp，绿色勾表示前台时 Dock 常驻显示。搜索可按应用名或包名筛选，未安装的历史包名不显示占位图标。

“诊断与日志”包含运行概况、诊断结果、日志上传、车控开关、诊断操作和可独立滚动的日志窗口。查看历史日志时暂停自动跟随，回到底部后恢复跟随。

当前日志页从上到下：运行概况；车控开关 / 日志上传；诊断结果 / 诊断操作；整行运行日志。两排卡片分别底部对齐。原有 5 个开关、9 个操作入口、上传地址提交逻辑、诊断结果回调和崩溃熔断保留。4.0 纯 UI 升级不会强制把现有车控开关恢复为开启。

还要开悬浮窗权限、通知使用权、前台应用检测。前台检测用来决定哪些应用藏 Dock，也用来判断是不是系统桌面。开通过一次之后，如果车机重启把这项从无障碍名单里拿掉，而本应用持有 `WRITE_SECURE_SETTINGS`，启动时会把它写回去。

## 七、签名与 GitHub Actions

本机 Release 使用 Android Studio 默认 debug keystore，签名证书 SHA-256：

```text
55:A8:61:3C:15:D7:0D:39:2A:E5:07:16:1C:B2:7C:1F:
E7:07:EE:68:02:00:97:7B:74:56:EA:0D:9E:2A:34:61
```

GitHub Actions 要与本机签名一致，需要配置以下 Secrets，并在 workflow 中解码和使用 keystore：

- `ANDROID_KEYSTORE_BASE64`
- `ANDROID_KEYSTORE_PASSWORD`
- `ANDROID_KEY_ALIAS`
- `ANDROID_KEY_PASSWORD`

不要把 keystore、Base64 内容或密码提交到仓库。构建后用 `apksigner verify --print-certs` 校验 SHA-256。

仓库已有 [Publish APK workflow](.github/workflows/release-apk.yml)：默认分支推送含发布关键词（如“发布”、`release`）的提交，或手动运行时，构建并使用四个 Secrets 重签 APK，然后发布版本、`update.json` 和 `SHA256SUMS`。普通文档提交不应带发布关键词，以免无意触发发布。

注意当前命名差异：Gradle 本地输出为 `Banana_Dock-4.0.apk`，现有 workflow 发布阶段仍命名为 `CarDockBar-4.0.apk`、Release 标题仍为 `CarDockBar 4.0`。本次只同步文档，没有修改远程 CI 的命名或发布策略。`.github/signing/ci-test.jks` 为已有 CI 测试文件，不是本机正在使用的签名，不要替代 Secrets 内的实际 keystore。

## 八、编译

JDK 用 Android Studio 自带的 JBR。`JAVA_HOME` 指到 `C:\Program Files\Android\Android Studio\jbr`。系统里的 Java 8 编不过。

```bash
.\gradlew :app:assembleRelease
```

产物：`app/build/outputs/apk/release/Banana_Dock-4.0.apk`。
